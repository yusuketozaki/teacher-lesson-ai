# 保留事項（Issue #6 の mock 試作時点）

mock 試作で「暫定」として実装した値や、根拠が不足しているため決めていない事項です。ここに書いた内容は決定事項ではありません。決まった時点で該当 Issue に記録し、この文書を更新します。

## 単元カタログと目標候補の根拠（#7）

- 単元の仮候補（`src/lib/lesson/catalog.ts`）は試作の画面を動かすための一般的な単元名で、**出典 URL・確認日・利用条件を記録していません**。権利確認済みの一次資料による裏付けがありません。
- 小5算数の全単元を網羅しているとは限らず、並び順は指導の順序を表しません。単元名や構成は教科書・地域によって異なります。
- 単元ごとの標準的な配当時間は持っていません。全授業数は教員が入力します。
- 授業位置（初回・中盤・最終）から目標候補を出す方法は mock の仮ロジックで、教育的な妥当性を確かめていません。
- 決めること: 候補の出典と範囲、更新方法、候補数、独自単元の扱い、根拠が不足する場合の表示。

## データ境界（#8）

- この試作では外部送信・永続保存をしていませんが、入力・編集項目ごとの許容例・禁止例・最小化策の定義、誤投入時の対応、確認担当、公開してよい検証記録の範囲は未定義です。
- 個人情報を入れない案内は表示しますが、検出や防止はしていません。
- 教材の権利確認と、学校・教育委員会の利用ルールの確認は、別々の確認事項として未実施です。

## AI の選定と生成契約（#9）

- **実 AI の提供者・モデル・費用上限・利用条件は選定を保留しています。** 実接続、API キー、課金は実装していません。
- 現在の入出力スキーマ（`src/lib/lesson/types.ts`、`schema.ts`）は mock 用の暫定案です。実 AI の構造化出力に合うかは未確認です。
- タイムアウト 10 秒、自動再試行なし、リクエスト回数・トークン上限なしは mock 用の暫定値です。
- 実接続前に、送信先とデータの扱いを画面に示す条件を決める必要があります。

## 入力・生成・編集の上限（#10〜#13）

- 文字数・時数・授業時間の上限（[mock 試作メモ](mock-mvp.md) の表）はすべて暫定値です。
- 授業時間は 5 分未満を受け付けません（mock の時間配分で各段階に 1 分以上を割り当てるための暫定の制約）。
- 目標候補の再生成は、同じ条件では同じ候補を返す（mock が決定的なため）。実 AI での再生成の扱いは未定です。
- 時間配分の各欄は 0〜999 の整数を数値として扱います。この範囲も暫定です。
- mock API は本文を読み込んでからサイズ上限を確認します（`Content-Length` がない場合を含む）。デプロイしないローカル試作のための簡易実装で、公開環境向けの対策ではありません。
