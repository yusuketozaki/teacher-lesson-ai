# 小5算数 mock 試作（Issue #6）

小学5年・算数の簡潔な授業案のたたき台を、教員が確認・編集・コピーする流れを **mock（固定テンプレート）** で試すための実装メモです。AI は使用していません。学校業務での利用許可、教材の権利、安全性、教科書・学習指導要領との整合、時短効果は検証も保証もしていません。

## 操作フロー

1. 学年「小学5年」・教科「算数」は固定表示。単元を試作用の仮候補から選ぶか、候補にない単元名を追加する。
2. 単元の全授業数、本時（何時間目）、授業時間（分）を入力する。
3. 条件に応じた本時の目標候補（mock）を表示する。教員が選択・修正し、「確認しました」にチェックするまで次へ進めない。
4. 確認済みの目標と条件から授業案（mock）を作る。
5. 目標、導入・展開・まとめの活動と時間、準備物、理解状況の確認方法を編集する。時間配分の合計と授業時間の一致・不足・超過・不正値を表示する（自動補正しない）。
6. 編集後の内容をテキストでコピーする。自動コピーに失敗した場合は、選択して手動でコピーする欄を表示する。

条件や確認済みの目標を変更する場合、また編集済みの授業案を作り直す場合は、破棄される内容を示して確認を求めます。古い条件に対する遅い応答で現在の内容を上書きしません。

## mock の性質

- 目標候補と授業案は、単元名と授業位置（初回・中盤・最終・1時間のみ）で文面を切り替える固定テンプレートです。算数としての正確さ、目標と活動の整合を判断していません。
- 時間配分は授業時間から一定比率で機械的に割り当てています。
- 応答は必ず `source: "mock"` を含み、画面にも mock であることを常時表示します。
- API: `POST /api/mock/goal-candidates`、`POST /api/mock/lesson-plan`。サーバー側で入力と出力の形式を検証し、不正・欠落・空の応答は授業案として表示しません。

## 暫定設計の値

次の値は試作を動かすための **暫定値** であり、合意済みの要件ではありません（#6、#9、#10 で別途決定）。定義は `src/lib/lesson/limits.ts` にあります。

| 項目                     | 暫定値                                    |
| ------------------------ | ----------------------------------------- |
| 単元名の文字数           | 1〜40 文字（前後の空白を除く）            |
| 全授業数                 | 1〜30 の整数                              |
| 本時                     | 1〜全授業数の整数                         |
| 授業時間                 | 5〜120 分の整数                           |
| 目標の文字数             | 200 文字まで                              |
| 活動の文字数             | 400 文字まで                              |
| 準備物・確認方法         | 各 1000 文字まで（1 行 1 項目）           |
| 目標候補の数             | 3 件                                      |
| リクエストのタイムアウト | 10 秒（自動再試行なし、手動の再試行のみ） |
| リクエスト本文の上限     | 8192 バイト                               |

候補にない単元名が仮候補の単元名と同じ（全角・半角や空白の違いを正規化して比較）場合は、候補から選ぶよう案内します。

## データの流れ（この試作の範囲）

| 場所                                               | 扱い                                                                                                                           |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 画面のメモリ（React の状態）                       | 入力・候補・授業案を保持。再読み込み・タブを閉じる・移動で消える                                                               |
| localStorage / sessionStorage / IndexedDB / Cookie | 授業案本文を保存しない（E2E で localStorage・sessionStorage・Cookie を確認。IndexedDB は使用していないが自動確認はしていない） |
| 自アプリのサーバー（mock API）                     | 単元名・条件・目標文を送信し、メモリ上で処理して応答する。アプリのコードは本文をログ出力・保存しない                           |
| データベース                                       | なし                                                                                                                           |
| 外部 AI・外部 API                                  | 送信なし                                                                                                                       |
| アクセス解析・クラッシュ報告                       | なし（`NEXT_TELEMETRY_DISABLED=1` は Next.js のビルド時テレメトリ設定）                                                        |
| コピー先                                           | 利用者のクリップボードと貼り付け先。アプリの管理外                                                                             |

ホスティング環境や逆プロキシのアクセスログは本試作の範囲外です。デプロイはしていません。離脱時にブラウザへ警告表示を依頼しますが、ブラウザが必ず警告を出すとは限りません。

## 検証方法

```sh
npm run check   # 整形・lint・型・単体テスト（node:test）
npm run build
npm run e2e     # Playwright（Chromium）。初回は npx playwright install chromium が必要
npm audit --audit-level=high
```

E2E は CI に含めていません（ブラウザのダウンロードが必要なため）。単体テストと E2E は架空の条件のみを使います。テストの内容と結果、未検証事項は PR に記載します。

未決事項は [保留事項](pending-decisions.md) にまとめています。
